# ABAP 规范审查清单

## 使用方式

交付代码、设计或对象定义前读取。只检查任务影响范围；不要把审查变成无关重构。标记“不适用”时说明所选档案或对象依据。

## 环境与规则

- [ ] 已选择 `CLASSIC_ECC`、`S4_CLASSIC`、`S4_CLEAN_CORE` 或 `ABAP_CLOUD`，并记录判定证据。
- [ ] 已确认 SAP 平台/语言版本、客户规范和项目规则的覆盖关系。
- [ ] 已确认模块、项目代码、开发类型、开发号、需求/问题号和投产状态中实际需要的信息。
- [ ] 没有把 `CLASSIC_ONLY`、`SUPERSEDED`、`PROJECT_CONFIG` 或 `SOURCE_CONFLICT` 当作无条件强制规则。
- [ ] 流水号、开发包、权限组、传输层和 API 发布状态来自当前系统或项目，不是推测。

## 架构与命名

- [ ] 对象类型适合所选档案；ABAP Cloud 未使用不允许的经典对象或未发布 API。
- [ ] Clean Core 已优先 Released API/Extension Point，并按 Tier 1/2/3 隔离例外。
- [ ] 经典对象使用正确 `Z`/`Y` 命名空间、模板和长度；现代对象遵循项目批准的分层命名。
- [ ] Includes 只用于经典适用场景，并按实际职责创建。
- [ ] 经典参数和对象前缀仅在项目要求时强制；现代名称表达业务语义。
- [ ] 原文冲突项已有项目依据，未静默猜测。

## 代码与数据访问

- [ ] 声明保持最小作用域，无 Header Line、`OCCURS` 和目标语言禁止的语法。
- [ ] 过程职责清晰、异常可识别；可复用层未耦合前台消息或任意提交事务。
- [ ] 无不必要宏、FORM、动态调用和不可追踪的数据簇操作。
- [ ] 内表类型、主键和 Secondary Key 与读取/更新模式匹配，不机械套用 BINARY SEARCH。
- [ ] 无循环内数据库访问和不必要往返，只取所需字段；JOIN/CDS/下推依据数据模型和测量判断。
- [ ] 没有用固定 JOIN 数量、WHERE 文本顺序或“配置表”标签替代性能分析。
- [ ] 代码注释解释原因；现代受版本管理代码未保留注释掉的旧实现。

## CDS、RAP、增强和持久化

- [ ] CDS 的字段、Association、Cardinality、语义注解和 DCL 与业务模型一致。
- [ ] RAP 的 Behavior、授权、锁、ETag、校验、动作和 Save Sequence 只启用实际需要的能力。
- [ ] 增强点保持薄层；经典增强函数或现代类/服务符合所选档案，同一需求关系可追踪。
- [ ] 域、数据元素、结构、表和公开 API 变更已做 where-used、兼容和下游影响分析。
- [ ] 经典表的 MANDT、Delivery Class、缓存、维护界面、审计、文本表、Check Table 和权限组根据用途与档案确定。
- [ ] 数据库更新有明确事务所有者、LUW、失败传播和恢复策略；Update Task 仅在需要该语义时使用。
- [ ] 生产持久化变更有迁移、部署顺序、验证和恢复方案。

## 安全与接口

- [ ] 入口执行适当的启动权限、`AUTHORITY-CHECK`、RAP 授权或 CDS DCL，并覆盖拒绝路径。
- [ ] 外部输入在进入动态 SQL/调用、文件、权限和持久化前经过白名单或业务校验。
- [ ] 日志与错误消息不泄露密钥、凭据、个人敏感数据和不必要技术细节。
- [ ] 经典汉硕 RFC 才应用 `ZINTF_MESSAGE`、`EX_S_MESSAGE`、`ET_MESSAGES`；现代接口使用自己的版本化错误契约。
- [ ] 可重试写接口明确幂等性，接口明确相关 ID、时间、币种、单位和分页中实际需要的语义。

## 测试、静态检查与交付

- [ ] 核心业务规则有 ABAP Unit，相关正常、边界、权限和失败路径已覆盖。
- [ ] 数据库、OO 或 RAP 依赖在目标版本可用时使用相应 Test Double 或隔离集成测试。
- [ ] 已运行语法检查和项目 ATC Variant；经典系统按需补充 SLIN/SCI。
- [ ] 错误为零；每条警告均已修复或有包含原因、责任人和有效期的豁免。
- [ ] 可用时执行 CVA/安全检查；不可用时说明未执行项和剩余风险。
- [ ] 传输对象、权限、配置、服务和 DDIC 依赖顺序已确认。
- [ ] 最终报告列出档案、检查范围、规则编号、修复、测试、豁免、未验证项和剩余风险。
