# SAP 问题排查

以“真实输入 → 业务适用范围 → 实际执行路径 → 最终导出”为主线，解释结果为何产生。将已验证根因、静态风险和待确认业务规则分别表述。完整排查默认保留关键截图并交付离线 HTML；用户指定其他格式或仅需简答时按其要求调整。

## 先确定范围

- 读取当前项目生效规则；遵守项目的临时目录约定。检查 Git 状态，保护用户已有修改。
- 从现有会话和资料识别目标系统、客户端、对象、用例、预期和实际结果。截图上的用例标题只是定位信息，不代表真实参数或结果。
- 查明测试是否会写业务数据、接口日志、更新任务或调用外部系统。只读分析不等于执行写接口的授权。若已有授权覆盖这次测试，不重复询问；否则先完成安全的只读检查，在需要执行前一次性说明具体副作用并取得授权。
- “排查”不自动包含修改活动对象、激活、传输、改主数据或修复代码。用户要求修复时再按相应授权实施。

## 建立事实链

1. **读取实际参数。** 复用用户指定的已登录会话，精确核对系统、客户端和对象。载入已准备的用例，核对请求类型、所有关键业务键及行数；不要凭用例名称推断分支。
2. **核对活动代码。** 通过显示权限读取问题相关源码，确认本地副本是否与活动版本一致；若不一致，以实际运行对象定位问题并报告差异。源码复制方式遵循现有 `sap-gui-automation` 技能；不要进入修改模式。
3. **对照需求。** 阅读相关 FS、接口契约和既有规则。区分“需求明确要求”“代码实际行为”“用户新增期望”。不要把一次用例的期望升级成所有接口的通用业务规则。
4. **追踪执行。** 在获准的测试中，观察入口、关键 SELECT/标准函数后、筛选与去重后、状态赋值处及最终导出。记录业务键、实际数量、返回码和是否真的执行了校验，不修改变量或跳转执行指针制造结果。
5. **独立核验关键数据。** 必要时用已有显示权限查询最小数据范围。记录所有筛选条件和客户端；区分“带关联条件未匹配”与“基础表确实不存在”。截图保留筛选和结果；无数据消息也是证据。
6. **解释根因与影响。** 每个结论绑定证据和对象/位置；指出直接触发条件、漏掉的业务范围、共享调用路径及未验证的相邻场景。只做与当前问题相关的扩展检查。

SAP GUI 及调试细节按需读 [references/gui-debugging.md](references/gui-debugging.md)。它补充现有 `sap-gui-automation` 技能，不替代其会话和权限规则。仅有本地资料时可继续静态分析，明确未动态验证的部分，不要求用户为了形式连接系统。

## 对“空数据仍成功”的专项检查

- 分清输出表承载正常结果还是异常明细；异常表为空不自动证明所有对象已校验，不能简单反转最终 IF。
- 跟踪输入对象是否在 INNER JOIN、工厂映射、类型筛选、去重或空驱动表分支中消失。混合请求需检查每个根对象，不能只看整个批次非空。
- 检查标准函数异常返回码是否立即处理；捕获异常后是否继续追加看似正常的数据；工作区是否残留上次调用内容。
- 区分不存在、不适用、处理失败和完整校验通过。是否“无 BOM 一律错误”等业务结论必须有当前需求依据。
- 需要保留根物料时，应独立建立根对象范围，再合并成功取得的下级数据；根对象保留不能依赖存在下级记录。

## 截图和交付

在状态易失前取证：实际请求、关键数据查询、中间结果、成功/失败赋值和最终输出。通常使用 SAP 官方 `HardCopy(path, 2)` 保存原始 PNG；模态窗口单独截图。保留完整原图，局部强调用报告布局表达，不用生成图片替代现场。

读 [references/report-contract.md](references/report-contract.md)，将证据和发现写入结构化清单，再用标准库脚本生成离线报告：

```powershell
python "<本技能目录>\scripts\build_report.py" "<案件目录>\case.json" --output "<案件目录>\SAP问题排查报告.html"
```

脚本内嵌原图、计算 SHA-256，并拒绝缺失截图、断开的证据引用及未授权覆盖文件。它只负责组织材料，不替代对截图内容和业务结论的核验。

无法取得截图时不伪造、不用示例图充当证据；交付中说明缺少哪项现场验证。纯静态案件可用源码摘录和文件哈希手工组织 HTML，不必为了调用截图报告脚本强行连接系统。

交付前检查图片内容、证据引用、源码行号及事实/推断区分；用可用浏览器验证页面加载、桌面与窄屏显示。不能运行浏览器时如实说明。完成测试后正常结束调试，保留业务错误现场，不自动确认警告。清理自行创建的临时脚本和不需保留的完整源码副本，保留正式截图和报告。最终说明根因、执行过的验证、是否改代码及报告位置。
