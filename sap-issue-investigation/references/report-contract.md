# 排查报告数据与验收

## 文件组织

案件资料放在用户项目约定的正式文档目录，临时脚本按项目规则另放。案件目录内保留 `case.json` 与原始截图；HTML 内嵌相同图片，可单独离线阅读。不要将客户案例的截图、物料号、服务器名或源码副本装入技能本身。

`build_report.py` 仅依赖 Python 标准库。输入和输出必须位于同一案件目录范围内；证据路径相对 `case.json`，只接受本地 PNG，不接受远程 URL、绝对路径、越界路径或空图。输出已存在时拒绝覆盖；只有当前任务确实允许替换时才传 `--overwrite`。

## case.json 示例

以下为合成示例。生成真实报告时全部替换为实际观察，删掉不适用条目；不要把该示例当作测试结论。

```json
{
  "title": "SAP 接口返回异常排查报告",
  "system": "TEST",
  "client": "100",
  "object": "Z_SAMPLE_QUERY",
  "summary": "按实际证据描述最重要结论。",
  "scope": "只读分析与已授权的测试；未修改活动源码。",
  "execution": "执行了哪些测试及副作用；未执行哪些检查。",
  "requirements": [
    {"source": "当前项目 FS 的相关段落", "text": "准确摘录或概括约定行为。"}
  ],
  "evidence": [
    {"id": "E01", "title": "实际请求", "path": "evidence/input.png", "observed_at": "2026-01-01T10:00:00+08:00", "note": "实际类型、业务键和数量。"},
    {"id": "E02", "title": "最终返回", "path": "evidence/output.png", "observed_at": "2026-01-01T10:05:00+08:00", "note": "状态、消息和返回明细。"}
  ],
  "findings": [
    {"id": "F01", "title": "有证据的根因", "status": "verified", "evidence_ids": ["E01", "E02"], "location": "对象 / Include / 已核验行号", "cause": "触发条件及实际执行逻辑。", "impact": "影响对象和调用方。", "recommendation": "范围明确、符合业务要求的修复。"}
  ],
  "path": [
    {"text": "实际请求进入的分支", "evidence_ids": ["E01"]},
    {"text": "最终返回的观察", "evidence_ids": ["E02"]}
  ],
  "checks": [
    {"name": "活动源码核对", "result": "实际执行结果与比较边界"}
  ],
  "limitations": ["未验证场景和仍待落实的业务规则。"]
}
```

`findings.status` 仅用 `verified`（已验证）、`static`（静态发现）、`candidate`（待验证）。每条发现和路径步骤必须引用至少一个存在的证据 ID。静态代码证据也可保存相应源码显示页 PNG，并在 note 中明确没有动态触发。不能将静态风险写成实际发生。

清单中的文字按普通文本渲染，脚本会转义 HTML。代码或调用路径可放在对应文字字段并保留换行；更复杂的报告布局可以在生成后按用户要求修改，但不能破坏证据引用和原图。

## 验收要点

- 结论与复现边界：目标系统/客户端/对象、用例和日期，真实输入类型，实际状态与导出值。
- 证据到发现再到执行路径：图可辨识，来源与筛选完整，图文一致；原始 PNG 的 SHA-256 可复算。
- 业务判断：区分现有契约与新增期望，不把“无数据”直接等同于“业务失败”，也不把“无异常记录”直接等同于“全部校验通过”。
- 修复建议：输入覆盖、异常传播、共享路径和向后兼容；不通过反转状态判断或添加无业务依据的兜底掩盖问题。
- 验证：列出真正执行的测试，不虚报 ABAP Unit、语法检查、ATC 或修复后回归；调试暂停时间不作为性能依据。
- 页面：图片内嵌可离线加载，原图可查看，文字对比清晰，窄屏无页面横向溢出，支持打印；没有可用浏览器时标注未做视觉验证。

脚本生成 `.evidence.json` 清单，含图像与输入清单的 SHA-256。这用于文件完整性核验，不证明截图的业务含义或真实性。
