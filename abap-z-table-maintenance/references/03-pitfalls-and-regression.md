## 1. 踩坑速查表

按「现象 → 根因 → 正解」排。前 6 条是编译期错误，后面是运行期语义错误。

| # | 现象 | 根因 | 正解 |
|---|---|---|---|
| P1 | 权限检查恒为无权限，`sy-subrc = 4` | `AUTHORITY-CHECK` 里写了权限对象**不存在**的字段（如补 `ID 'ACTVT' DUMMY`）→ 检查根本无法执行 | 只写权限对象里**真实存在**的字段。漏写「对象里有」的字段只是不检查，不影响结果；写「对象里没有」的字段则直接判无权限 |
| P2 | SE24 报「显式长度说明必须与面向对象上下文中的类型 C、P、X 和 N 一起使用」 | 类定义（OO 上下文）里写了 `box TYPE c` | `box TYPE c LENGTH 1`（等价 `TYPE char1`）。实证边界：程序里的普通 `DATA`、带 `VALUE` 的常量、方法参数位 `iv_mode TYPE c` 都不报错 |
| P3 | `"LT_FIELDCAT" 与形式参数 "IT_FIELDCATALOG" 类型不兼容` | **表键算类型的一部分**。形参是默认键（`LVC_T_FCAT`），实际参数写成 `WITH EMPTY KEY` | `DATA lt_fieldcat TYPE lvc_t_fcat.`。凡是「取出 → 改 → 送回」框架/ALV 的内表，表键必须与形参一致 |
| P4 | `PERFORM ... USING e_row-index` 报类型 70 | `LVC_S_ROW-INDEX` 是 **NUMC(10)**。赋值允许隐式转整型，**参数传递不允许** | 先 `DATA lv_index TYPE sy-tabix. lv_index = e_row-index.` 再传。行号形参统一 `TYPE sy-tabix` |
| P5 | 语法检查报「MODULE 不能在此调用」 | dynpro **MODULE 不能被 METHOD 调用** | 需要复用的逻辑放 FORM，MODULE 里只留 `PERFORM`。ALV 事件 handler 要转交 PAI 逻辑时，把 `CASE` 抽成 FORM |
| P6 | 静态 GUI 状态里配了按钮，界面上却没有／点了没反应 | 按钮机制要么靠 SE41 的 GUI 状态（源码里看不到），要么靠代码 `add_button`「两处都必须改」 | 新增按钮：① GUI 状态加功能码 + Icon Text；② 代码 `CASE` 加分支。缺一不可 |
| P7 | 空值主键加锁后，**整个公司+年月**都被锁住；解锁时还释放了别人的锁 | `ENQUEUE` 参数留空 = **所有值**（泛化锁） | 可空维度必须 `X_<字段> = 'X'` 显式声明「初值也参与锁定」；`DEQUEUE` 的主键与 `X_` 必须与加锁完全一致 |
| P8 | F4 选完了，屏幕字段还是空的 | **POV/POH 结束后直接回屏幕，既不触发 PAI 也不触发 PBO** | F4 模块里改完内存后必须 `DYNP_VALUES_UPDATE` 写回；这是唯一回填途径 |
| P9 | F4 里读到的字段是旧值 / 空值 | POV 只执行该字段关联的**第一个**模块，且**字段内容不会自动传进来** | 在 F4 模块内用 `DYNP_VALUES_READ` 自取屏幕当前值 |
| P10 | F4 弹窗后报 `DYNPRO_MSG_IN_HELP` 或帮助直接中断 | 帮助上下文里发了 E 类消息 | F4（`ON VALUE-REQUEST`）里禁止 E 消息，一律 `MESSAGE ... TYPE 'S' DISPLAY LIKE 'E'` |
| P11 | 错误消息被截断 300 字符 / 消息号丢失 | 用了 `lx_xxx->get_text( )`，走 `MESSAGE text` 变体 | 直接传异常对象：`MESSAGE lx_xxx TYPE 'S' DISPLAY LIKE 'E'.` |
| P12 | 本来想给「提示」级别，结果弹成红色错误 | `TYPE ... DISPLAY LIKE ...` 里的 `TYPE` 被省掉，隐式取了原消息类型 | `TYPE 'S' DISPLAY LIKE 'E'` 两个都要写全 |
| P13 | ALV 工具条自定义按钮点了没反应 | 未注册 ALV 的 **`user_command` 事件** —— 自定义按钮的功能码只通过该事件送达，不会自动进 dynpro PAI | `SET HANDLER ... on_user_command`，并在 handler 里转交 PAI 处理逻辑 |
| P14 | 首次进入列表时自定义按钮不显示 | `SET HANDLER` 晚于 `set_table_for_first_display`，`toolbar` 事件已经过 | handler 注册放在首次显示之前 |
| P15 | 保存失败后，别人反而拿不到锁 / 自己的锁没释放 | 异常路径没解锁，或 `COMMIT WORK` 后服务层已解锁而界面又解一次 | 统一：所有失败路径 `ROLLBACK WORK` + 解锁；成功后界面同步把锁标记置假 |
| P16 | 两人同时改同一条，后提交的把先提交的覆盖了 | 只靠排他锁不够（锁在窗口打开时持有，但列表数据可能是旧的） | 三道保护：① 打开窗口前加锁并**重读数据库**；② 保存时比对 `AENAM/AEDAT/AEZET`；③ 列表缓存不作为修改依据 |
| P17 | 列表里「公司级」配置全被标成红色（映射缺失） | 校验映射唯一性前没判空 —— 分层配置里上级记录本来就没有下级客户号 | 校验前 `IF kunnr IS INITIAL. CONTINUE. ENDIF.`；关联名称表的 SQL 用 `LEFT OUTER JOIN`，空值行不会丢 |
| P18 | 取消弹窗后列表滚动位置和选中行没了 | 无条件刷新列表 | 脏标记：只有确实落库才刷新；取消/校验失败不动列表 |
| P19 | 用户「没重新选过」就操作了同一条记录 | 上一轮操作后勾选残留 | 每次操作结束调 `clear_marks` 清勾选 |
| P20 | 用户勾了 3 条点「修改」，只改了第 1 条且无提示 | 用 `READ TABLE ... WITH KEY box = 'X'`（静默取第一条） | LOOP 计数校验：0 条 / 多条都拒绝 |
| P21 | 列表被 MANDT、审计字段、内部金额列塞满 | 字段目录直接用了框架生成的「全部字段」 | `CASE fieldname` 白名单 + `WHEN OTHERS → DELETE lt_fieldcat` |
| P22 | 改完代码，问题还在（或改错了地方） | **没有先验环境与平台语义** | 排查纪律：先确认是环境/平台行为还是代码问题，再动代码。文档化误判结论，避免反复踩 |
| P23 | 要求「把某个表字段也加到列表上」，一上来就去改表结构 / 改 SQL | 列表行类型多半写成 `INCLUDE TYPE <主表>`，取数 SQL 也常已把整行取回。字段其实早就读进内存了，只是被 `WHEN OTHERS → DELETE` 白名单裁掉了 | **先查三处再动手**：① `ty_list` 是否已含该字段 → ② 取数 SQL 是否已 `SELECT` 它 → ③ 字段目录白名单是否把它裁掉。多数「加一列」的真实改动面只有第三处，前面两步纯属白改 |
| P24 | 新增的列用户看不见；或已有列的顺序/位置被打乱 | ① 动了已有列的 `col_pos` → 用户存过的 ALV 布局变式列序错位；② 布局变式里没有新列 → 新列默认不显示 | 新列 `col_pos` **接在末尾**，已有列一个都不动；实施后提醒用户**删掉旧布局变式或另存一份**。另：`set_editable( abap_true )` 全局开编辑时，新列必须逐列补 `edit = abap_false`，否则审计字段变成可输入格子 |

## 2. 正反例对照（三个最容易分歧的写法）

### 2.1 取行

```abap
" ✗ 静默取第一条：勾多条只改一条，勾 0 条静默返回
READ TABLE gt_list WITH KEY box = 'X'.
IF sy-subrc = 0. ... ENDIF.

" ✓ 计数校验，语义「恰好一条」
LOOP AT gt_list ASSIGNING FIELD-SYMBOL(<ls>) WHERE box = 'X'.
  lv_count = lv_count + 1.
  lv_index = sy-tabix.
ENDLOOP.
IF lv_count = 0.  MESSAGE '请先勾选一条记录' TYPE 'S' DISPLAY LIKE 'E'.  RETURN.  ENDIF.
IF lv_count > 1.  MESSAGE '请只勾选一条记录' TYPE 'S' DISPLAY LIKE 'E'.  RETURN.  ENDIF.
```

### 2.2 可编辑控制

```abap
" ✗ 全局开编辑、只给 BOX 列 set_edit —— 其他列看着能改，改完不落库（假可编辑）
go_alv->set_editable( abap_true ).
go_alv->column( 'BOX' )->set_edit( abap_true ).

" ✓ 字段目录里逐列显式写 edit
"    BOX  → edit = abap_true
"    其余 → edit = abap_false
"    再叠加 column( 'BOX' )->set_edit( abap_true ) 双保险
```

### 2.3 批量操作的事务

```abap
" ✗ 逐条 DELETE + COMMIT WORK AND WAIT + WAIT UP TO '0.5' SECONDS，且不检查 sy-subrc
"    → 慢、不可回滚、部分成功无感知。不要带到任何批量场景。

" ✓ 单条走「校验 → 加锁 → 重读 → 写 → COMMIT WORK AND WAIT」，
"    异常路径 ROLLBACK WORK + 解锁；
"    真正的批量用一次 COMMIT，并收集失败明细反馈给用户。
```

## 3. 上线前回归清单

按此表逐条过。带 ⚠ 的是最容易被跳过、也最容易出事的。

| # | 场景 | 预期 |
|---|---|---|
| T01 | 列表查询：多公司 / 空条件 / 仅单公司 | 有权限公司全部返回；无权限公司被静默过滤 |
| T02 | ⚠ 无权限公司 | 查询：列表不出现该公司数据；新增/修改：报无权限（e011）；F4：提示无权限且不泄露数据 |
| T03 | 新增成功 | 提示成功、列表出现新记录、审计字段 `ERNAM/ERDAT/ERZET` = 当前用户/日期/时间 |

| T05 | ⚠ 新增时清空上级字段（分层配置） | 非法组合被拒（如「有下级无上级」），提示明确 |
| T06 | 修改成功 | 列表内容更新；`ERNAM/ERDAT/ERZET` 保持原值，`AENAM/AEDAT/AEZET` 更新 |
| T07 | ⚠ 并发修改：A 打开窗口 → B 改并提交 → A 保存 | A 被拒绝并提示最新修改人/时间，不覆盖 B |

| T14 | ⚠ F4（每个可助益字段各测一次） | 帮助能打开、按上级条件过滤、选中后**屏幕立即刷新**（关联字段一并回填） |

| T19 | 业务规则边界：档位连续性 / 比率 0、100、超范围 / 金额 0 / 非法年月 | 各自给出明确提示，不落库 |

## 4. 评审这类程序时的检查顺序

1. **权限**：对象字段与 `AUTHORITY-CHECK` 是否一一对应；服务层是否复校验
2. **并发**：加锁字段是否含 `X_`；窗口打开前是否重读库；是否有时间戳比对；退出是否解锁
3. **事务**：`COMMIT/ROLLBACK` 与 `sy-subrc` 检查；异常路径是否解锁
4. **取行语义**：是否「恰好一条」；失效行是否提示刷新
5. **刷新粒度**：是否有脏标记；取消操作是否污染列表状态
6. **图层归属**：业务判断是否混进界面；界面是否只做收集/展示/转发
7. **F4**：是否自取屏幕值、是否 `DYNP_VALUES_UPDATE`、是否误发 E 消息
8. **列表可读性**：字段是否白名单裁剪、列序是否固定、是否只有 BOX 可编辑
9. **异常展示**：是否统一走异常对象 + `TYPE 'S' DISPLAY LIKE 'E'`
