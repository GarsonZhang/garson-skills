# ABAP Z 表维护程序开发规范

样板来源：德保项目 `ZFI_R_0071`（销售折让配置维护，已完成类化/服务化改造），参照程序 `ZFI_E_001`。
本 skill 把这套实现方式固化为可复用规范 —— 下一个 Z 表维护程序照此套用，不必重新设计。

## 适用范围

**单表（或主表 + 映射表）配置维护**，主键含公司/期间/客户等业务维度，数据量中小（千级以内），
由人工增删改 → 选择屏幕查询 + 只读列表 + 弹窗编辑。

不适用：只读报表、批处理、接口/RFC、多表复杂事务。

## 0. 动手前必须确认（缺一项先问，不要猜）

| # | 要确认的事 | 为什么 |
|---|---|---|
| 1 | 表结构：主键、字段语义、哪些字段**分层可空**（如公司级 / 客户级两档） | 决定校验规则与取数回退逻辑 |
| 2 | 权限对象名及**其真实字段清单** | 写对象里不存在的字段 → 检查无法执行 → 全体判无权限 |
| 3 | 锁对象是否已生成（`ENQUEUE_E<表>`） | 决定并发保护方式 |
| 4 | 列表用哪套 ALV：公司框架 `zcl_alv` 还是原生 `cl_gui_alv_grid` | 决定屏幕与事件写法（见 02 第 1 节） |
| 5 | 弹窗字段分组（只读组 / 主键组 / 输入组） | 决定 `LOOP AT SCREEN` 控制哪些字段 |

## 1. 交付纪律（硬规则）

- **不直接改 SAP 侧导出的 `*.abap` 副本**。一律交付「改动说明」：位置 + 可照抄代码 + GUI 操作步骤。
- 新增 `.md` 文档可以直接写。
- 注释一律中文、写在被注释代码**上方**、讲「为什么」不只讲「做了什么」。
- 删数据、改表结构、数据迁移：先确认再动。

## 2. 标准分层

| 对象 | 命名 | 职责 | 关键约束 |
|---|---|---|---|
| 主程序 | `ZFI_R_xxxx` | 选择屏幕、列表、弹窗、界面事件、界面校验 | 界面只做「收集 + 展示 + 转发」，业务判断不留在这里 |
| 服务类 | `ZCL_<域>_SERVICE` | 取数、编排校验、加锁、权限、事务 | `CREATE PRIVATE` + 全静态方法 |
| 校验类 | `ZCL_<域>_VALIDATOR` | 纯函数：单位换算、范围/序列/格式校验 | 不访问数据库，可被 ABAP Unit 直接覆盖 |
| 异常类 | `ZCX_<域>` | 业务异常 | 继承 `CX_STATIC_CHECK`，实现 `IF_T100_MESSAGE` + `IF_T100_DYN_MSG`，构造器带 `TEXTID` |
| 消息类 | `ZFI00xx` | 全部业务消息 | 校验失败 `e0xx`；界面提示 `s0xx` |

两类结构：

- `ty_list`（列表行）= `INCLUDE TYPE <表>` 展开的表字段 + 展示字段（`BOX` / `ICON` / `MESSAGE` / 名称类字段）
- `ty_edit`（弹窗字段）= 可编辑字段 + **审计字段**（`ERNAM/ERDAT/ERZET/AENAM/AEDAT/AEZET`，用于并发比对）

## 3. 实现顺序

| 步骤 | 内容 | 验收点 |
|---|---|---|
| S1 | 表 + 锁对象 + 消息类 | 主键、审计字段齐全 |
| S2 | 校验类 | 纯函数；边界值可单测 |
| S3 | 服务类 | 每个 public 方法只做一件事；权限/锁/事务边界清晰 |
| S4 | 主程序界面 | 列表可查、弹窗可增改删、F4 可用 |
| S5 | 屏幕与 GUI 状态 | 按最终形态确定（见 02 第 7 节） |
| S6 | 回归 | 跑 `references/03` 的清单 |

## 4. 十二条实现约定（每条都是踩过的）

1. **权限**：`AUTHORITY-CHECK OBJECT '<obj>' ID '<字段>' FIELD <值>.` 只写对象里**存在**的字段，`sy-subrc = 0` 才算有权。
   界面校验只为尽早反馈，**服务层必须重新校验**（防止绕过界面或窗口打开后权限被撤销）。
2. **加锁**：`ENQUEUE` 必须用 `X_<字段> = 'X'` 显式声明「初值也参与锁定」。
   否则空值会被当作**泛化锁**，锁住整个上级维度（如整个公司+年月），`DEQUEUE` 还可能释放别人的锁。
   加锁主键 = 解锁主键。
3. **锁的生命周期**：窗口打开前加锁 → 保存 / 取消 / 异常路径都要解锁；
   `COMMIT WORK` 后服务层已解锁，界面要同步把锁标记置假，避免重复解锁。
4. **事务**：`COMMIT WORK AND WAIT` + 检查 `sy-subrc`；异常路径 `ROLLBACK WORK` + 解锁后再 `RAISE`。
5. **并发第二道防线**：修改时比对库里旧记录的 `AENAM/AEDAT/AEZET` 与界面带回的值，不一致 → 拒绝覆盖并提示。
6. **列表取行**：用 `BOX` 勾选列 + **计数校验**（0 条与多条都拒绝）。
   不要用 `READ TABLE ... WITH KEY box = 'X'`（静默取第一条，勾多条只改第一条且无提示）。
7. **刷新**：引入脏标记（如 `gv_list_dirty`），只有确实落库才置真；返回列表后由 `refresh_if_dirty` 决定是否重读，
   避免「取消也刷新」丢失滚动位置与选中行。
8. **清勾选**：每次操作结束后清掉残留勾选，否则用户会在「我并没有重新选过」的感知下操作同一条数据。
9. **F4 搜索帮助**：统一 `F4IF_INT_TABLE_VALUE_REQUEST`；报错条件写 `sy-subrc <> 0 AND sy-subrc <> 2`
   （`2` = 无可用值，不是错误）；**F4 上下文禁止发 E 类消息**，一律 `MESSAGE ... TYPE 'S' DISPLAY LIKE 'E'`。
10. **F4 回填**：F4 模块里改的字段不会自动显示，必须 `DYNP_VALUES_UPDATE` 写回；
    读取屏幕当前值用 `DYNP_VALUES_READ`。
11. **异常展示**：界面统一 `MESSAGE lx_xxx TYPE 'S' DISPLAY LIKE 'E'.`，**传异常对象**、不要 `->get_text( )`；
    `TYPE ... DISPLAY LIKE 'E'` 不能省（省略会隐式取原消息类型，多为 E）。
12. **类型**：OO 上下文（类定义）里 `c/n/p/x` 必须写 `LENGTH`；
    回传给框架的内表表键必须与形参一致（字段目录用 `lvc_t_fcat`，不要 `WITH EMPTY KEY`）。

## 6. 交付物格式（改动说明）

固定六段，缺一不可：

1. **结论前置** —— 改什么、为什么、有什么影响（尤其「哪些东西会被删掉」）
2. **逐处改动** —— 位置（文件:行）+ 改前 / 改后
3. **可照抄代码** —— 每段带中文「为什么」注释
4. **GUI 操作步骤** —— SE11 / SE24 / SE38 / SE51 / SE41 逐条写清
5. **回归清单** —— 从 `references/03` 裁出与本改动相关的条目
6. **风险与未决点** —— 无法自查的前置条件要显式列出（如某类在目标系统是否存在）
